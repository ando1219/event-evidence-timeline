# 事件证据时间线（题目 08：投资事件情报与证据时间线）

同一个投资事件会以传闻、自媒体转载、媒体报道、公司回应、正式公告、更正公告、监管问询等形式不断演化。
这个产品把这些信息拆成一条条**带出处的主张**，用**确定性规则**算出"截至某一时刻"每个关键事实的当前结论，
让用户看清：最初来源是谁、事实怎么变的、哪里有冲突、现在处于什么状态、和自己关注的标的有什么关系。

> 本产品只整理事实与证据，不预测涨跌，不提供买卖建议。

## 一分钟看懂

打开首页 → 点进「辰星电子拟收购海岳光芯」（构造样例）→ 拖动顶部时间轴：

| 时间点 | 系统给出的结论（交易对价） | 原因 |
|---|---|---|
| 09-01 21:40 | 未证实：约 30 亿元 | 只有股吧传闻 |
| 09-02 08:15 | 未证实：约 30 亿元，并提示「转述走样」 | 自媒体转载时把 30 亿写成 35 亿；转载不提升证据等级，走样内容不参与判定 |
| 09-02 10:05 | 媒体报道·待证实：约 25 亿元 | 财经媒体 A（匿名信源）覆盖传闻 |
| 09-02 12:30 | **存在冲突**：25 亿 / 28 亿 | 两家同等级媒体说法不同，产品不替用户选边 |
| 09-02 19:30 | 已确认：尚未确定 | 公司在互动平台回应：价格未定；同时否认"下周停牌" |
| 09-15 20:00 | 已确认：22.8 亿元（暂定） | 正式公告 |
| 09-16 09:30 | 不变，媒体 A 旧版本作废 | 媒体 A 更新原文（更新时间≠披露时间） |
| 09-22 20:00 | 股权比例 51% → 55% | 公司发布更正公告 |

其它可以看到的规则：传闻里的"定增募资 10 亿"14 天无人证实 → 自动变为「已过期·未证实」，直到 09-28 公司公告给出真实资金来源；
交易所关注函要求 09-25 前回复，09-26 起提示「逾期待核实」，09-28 回复后提示消失。

## 产品选择

- **基本单位是"主张"而不是"新闻"**：每条主张 = 来源 × 事实槽位 × 取值 × 性质（事实/观点/推测/传闻）× 动作（提出/否认/更正/撤回）× 原文片段。
- **AI 只做抽取，结论由规则计算**：LLM 负责从原文抽主张；当前结论由 `app/engine.py` 的规则引擎计算。好处是可测试（75 个单元测试）、可解释（每条结论都能点回原文和触发它的来源）、不会"编结论"。
- **时间回放**：任意时刻只使用当时已生效的证据重算结论，这是理解"事实怎么变"的最直接方式。
- **只推送状态变化**：关注列表和事件卡片展示的是结论变化（如"传闻 → 公司否认"），而不是每一篇新文章。
- **MVP 只做一种事件类型（并购重组）**：槽位清晰、演化链条长，最能体现溯源、冲突和更正。

### 证据规则（`app/engine.py`）

1. 来源等级：公告/监管(6) > 公司回应(5) > 财经媒体(4) > 研报(3) > 自媒体/异动解读(2) > 传闻(1)。转载继承原始来源等级。
2. 证据权重 = 来源等级分 × 性质系数 × 出处系数（官方/署名/匿名）× 时效衰减（传闻、推测半衰期 7 天）。同一原始来源的多次转载只算 **1 个独立来源**。
3. 观点、推测不进入事实判定，单独展示（如研报"预计增厚 EPS"、媒体"或上调至 26 亿"）。
4. 原文更新：新版本生效后，旧版本中的主张全部作废。
5. 更正 / 撤回：作废同一发布方更早的说法。同一发布方以最新说法为准。
6. 否认：作废更早的、等级不高于否认方的说法；低等级否认高等级说法 → 标记冲突，需人工核实。
7. 冲突：静态事实（如对价）同等级不同发布方取值不同 → 「存在冲突」；进展类事实（交易进展、停牌、监管问询）同等级以最新为准。
8. 过期：只有传闻/自媒体支撑、14 天无更高等级来源证实 → 「已过期·未证实」；带截止日期的事项逾期未更新 → 「逾期待核实」。
9. 四类时间分开记录：事件发生时间、披露时间、抓取时间、更新时间。结论按生效时间（有更新则取更新时间）计算；抓取晚于生效 6 小时以上提示；披露时间按"15:00 前当日、之后顺延"换算为首个可交易日（扶摇交易日历）。

## 启动方式

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # 按需填写，不填也能运行（构造样例 + 规则抽取）
uvicorn app.main:app --reload --port 8000
# 打开 http://localhost:8000
```

测试：

```bash
pytest -q                   # 或：python -m unittest discover -s tests -t .
```

部署（Render）：仓库根目录已有 `render.yaml`。在 Render 选择 New → Blueprint，连接仓库，填入密钥类环境变量即可。
免费实例的磁盘不持久，运行中导入的数据在重启后会丢失（构造样例始终存在）。

## 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `FUYAO_API_KEY` | 否 | 扶摇 API Key（请求头 `X-api-key`）。不填时行情、交易日历、标的校验显示「未配置」 |
| `FUYAO_BASE_URL` | 否 | 默认 `https://fuyao.aicubes.cn` |
| `LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` | 否 | OpenAI 兼容接口。不填时导入使用规则抽取，并在界面标注「规则兜底」 |
| `IFIND_MCP_URL` / `IFIND_MCP_TOKEN` / `IFIND_MCP_AUTH_HEADER` | 否 | iFinD MCP 地址与凭证 |
| `IFIND_NEWS_TOOL` | 否 | iFinD 新闻检索工具名，先访问 `/api/ifind/tools` 查看 |
| `RUNTIME_DATA_FILE` | 否 | 导入数据落盘位置，默认 `data/runtime.json`（已加入 .gitignore） |
| `DEMO_NOW` | 否 | 固定"当前时间"，用于演示与测试 |
| `HTTP_TIMEOUT` | 否 | 外部请求超时秒数，默认 12 |

## AI 的角色

| 环节 | AI 做什么 | 怎么防止出错 |
|---|---|---|
| 主张抽取 | LLM 按 schema 输出槽位、取值、性质、动作、原文片段（`temperature=0`） | 引用片段必须在原文中逐字找到，否则拒绝；槽位/枚举/数值格式校验；拒绝记录在界面可见 |
| 事件归并 | 抽取出的标的参与打分 | 打分规则透明（主体名、关键词、时间距离、标的一致），未达阈值则新建事件并标注"待人工确认" |
| 结论计算 | **不参与** | 规则引擎计算，全部单测覆盖 |
| 问答 | **不参与生成** | 只从当前结论拼装答案并附出处；涉及涨跌预测、买卖建议的问题直接拒答 |
| 降级 | LLM 未配置或调用失败 → 规则抽取 | 界面与抽取日志都显示降级原因和置信度 |

开发过程中的 AI 使用与修正记录见 [docs/AI_USAGE.md](docs/AI_USAGE.md)。

## 数据来源

| 数据 | 来源 | 现状 |
|---|---|---|
| 演示事件的全部来源与主张 | `data/demo_events.json`，**构造样例** | 公司、文本均为虚构，主张为人工标注，作为抽取基准和测试夹具 |
| 行情快照 / 历史 K 线 / 交易日历 / 标的检索 | 扶摇 REST API | 已接入；配置 Key 后生效 |
| 新闻 | iFinD MCP（Streamable HTTP） | 接入层已实现并有单测，**未用真实账号联调** |
| 扶摇「资讯事件库」 | — | 文档注明暂不开放外部接入，因此未使用 |
| 关注列表 | 构造的匿名持仓 + 用户手动添加 | 不涉及真实用户数据 |

所有外部调用统一返回 `DataResult`（正常 / 缺失 / 调用失败 / 未配置），界面逐项显示状态和原因；接口失败或返回为空时不会显示成"正常"。

## 已知边界

- 只支持并购重组一类事件；其它类型的文本会被归为"待确认事件"，槽位可能抽不全。
- 规则抽取（无 LLM 时）只覆盖常见句式，置信度标为 0.5；正式使用应配置 LLM。
- iFinD MCP 的工具名与返回字段因账号而异，字段映射是宽松匹配，需要真实账号验证。
- 事件归并是关键词 + 规则打分，同名公司、简称变化等情况可能误合并，界面会展示打分理由。
- 与关注标的的关系只有三类：直接当事方、事件中列出的相关方、同概念标签；不推断产业链上下游，也不判断影响方向。
- 交易日历只覆盖近一年；超出范围或未配置时按工作日估算，未剔除法定节假日，界面会标注"估算"。
- 演示数据为构造样例，未关联真实公司和真实行情。

## 未做事项

- 多事件类型（定增、减持、业绩预告、监管处罚等）的槽位定义。
- 事件人工合并 / 拆分的操作界面。
- 用户账户与持久化数据库（当前为内存 + 可选 JSON 落盘）。
- 结论变化的主动推送（邮件 / 消息）。

```
  main.py            FastAPI 路由（薄层）
  service.py         业务服务：事件、关注、导入、行情、问答
  engine.py          规则引擎：权重、否认/更正/过期、冲突、溯源、结论变化
  extractor.py       LLM 抽取 + 规则兜底 + 原文校验
  clustering.py      事件归并打分
  compliance.py      合规：拒答预测与建议，问答只基于结论
  models.py schemas.py store.py config.py
  datasources/       fuyao.py（扶摇）、ifind.py（iFinD MCP）、calendar.py（交易日换算）
static/              前端（原生 HTML/CSS/JS，无构建步骤）
data/demo_events.json 构造样例
tests/               75 个单元测试
docs/                AI 使用与验证记录、测试说明
```
